- expect: green; tests on recorded NBK XML fixtures (no live call) show a good rate parsed for USD and EUR, a malformed or incomplete file and a rate ≤ 0 throwing `SourceFailureException`, a rate older than `signalbot.fx.max-age-days` (5) treated as stale, and a BUY rejected with "FX rate unavailable (…)" while a SELL still goes through
- why: `adapters/src/main/resources/application.yml:16` — `signalbot.fx.usd-kzt` is a hand-typed constant (`${FX_USD_KZT:525.0}`) that never ages, and every BUY's size in KZT depends on it (D-003 via `FxConverter`); found by SB-042, executor, 2026-11-28

Follow `docs/fx-source.md`. Put an `FxRateSource` behind `FxConverter` (it stays the only FX rule): an NBK adapter
reading the official rates XML on startup and daily at 18:00 Asia/Almaty, keeping the last good rate with NBK's own
date, and a fixed source (the current properties) selected only by `signalbot.fx.source=fixed`, used by tests. A
failed read throws (D-001); a missing or stale rate rejects every new BUY with a reason and an operator alert, never
falls back to the constant; exits and SELLs do not depend on it. Tests use fixture files only. Check the NBK URL and
XML shape by hand first (the research could not); if the format differs from the note, park with the real sample.
