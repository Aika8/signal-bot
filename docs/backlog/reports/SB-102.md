# SB-102 — Domain and application stay framework-free

Test: `application/src/test/java/io/github/signalbot/application/PurityTest.java` (plain JUnit, no new dependency).
It walks `../domain/src/main/java` and `src/main/java` (relative to the `application` module) and fails on any line
that imports — plainly or `static` — a package starting with `org.springframework`, `java.sql`, `java.net`,
`jakarta.`, `com.anthropic` or `org.telegram`. The match is on a whole package name (`java.sqlx` would not count),
and only on `import` lines, so a comment or string that mentions `java.net.URI` does not trip it. The failure message
lists every hit as `<root>/<file>:<line>: <import>`.

Result on 2026-11-27: 54 source files scanned, no hits.

Checked by hand: a temporary `import java.net.URI;` in `EarningsBlackout.java` turned the test red with
`src/main/java/io/github/signalbot/application/risk/EarningsBlackout.java:3: import java.net.URI;`; reverted.

Limit: a fully qualified use without an import (`java.net.URI.create(...)` in code) is not caught; the task asks
for imports only.
