# SB-101 — No port can place an order

Test: `domain/src/test/java/io/github/signalbot/domain/NoOrderPortTest.java`. It walks
`domain/src/main/java/io/github/signalbot/domain/port`, loads each class by name, keeps the interfaces and fails if a
declared method name contains `order`, `place`, `submit` or `trade` (case-insensitive). The failure message lists
the offending methods and every port method found.

Ports and methods found on 2026-11-27 (all pass the rule):

| Port | Methods |
|---|---|
| CashReader | read |
| DecisionEngine | decide |
| EarningsCalendar | upcoming |
| MarketClock | isOpen, nextOpen, nextClose |
| MarketDataFeed | subscribe, snapshot |
| NewsFeed | newsSince |
| Notifier | send, alert |
| PaperWallet | apply, applyAt (two overloads) — the listed exception, by exact name |
| PortfolioReader | read |
| PriceHistory | dailyBars |

`DecisionFailedException` and `SourceFailureException` live in the package but are classes, not ports, and are skipped.

Note: none of the `PaperWallet` method names actually contains a forbidden word today; the exception is kept as the
task asks, and a second test fails if an exception names a method `PaperWallet` no longer declares (so the list
cannot go stale silently). Checked by hand that a temporary `placeOrder()` port turns the test red.
