# SB-034 — After an exit fired, a restart does not fire it again (#31)

Test: `adapters/src/test/java/io/github/signalbot/trigger/ExitRestartTest.java`, with an in-memory
`PositionGuardStore` fake (same semantics as the SQL). Two cases, each driven as the live paths do it
(`ExitGuard.onPrice` → `ExitGuardHandler.handle` on a signal → `TrailingStateWriter.afterPrice`):

- **stop**: guard stored and armed at stop 96; price 95 fires `EXIT_STOP`, the handler submits the SELL (the gateway
  is prompted). A new `ExitGuard` + `GuardLoader.run` over the same fake arms nothing for AAPL; 95 and 50 fire nothing.
- **trailing**: stop 96, trailing 108/2/0.2; 108 activates, 115 is the best, 112.9 fires `EXIT_TRAIL`, the SELL is
  submitted. After the restart AAPL is not armed, has no trailing state, and 112 and 95 (below the stop) fire nothing.

**Result: the issue does not reproduce. Both tests passed on the unchanged code; no production file was changed.**

Why it holds — `ExitGuardHandler.java:51-52`, the first thing `handle` does:

```java
exitGuard.disarm(symbol);
guardStore.delete(symbol);
```

`GuardLoader.run` (`GuardLoader.java:37-41`) re-arms only rows that `findAllGuards()` returns, so a deleted row is
never re-armed. The trailing writer called after the handler finds no snapshot (the guard is disarmed) and writes
nothing, so it cannot bring the row back.

Checked by hand: with line 52 (`guardStore.delete(symbol);`) commented out, both tests fail; restored.

Remaining gaps (not fixed here, recorded as tech debt):

- a crash or restart **between** `ExitGuard.onPrice` and `ExitGuardHandler.handle` — the in-memory guard has marked
  the level fired, but the row is still stored, so the next start re-arms it and the exit fires again
  (`docs/backlog/tech-debt/2026-11-27-SB-034-1.md`). This is the only path on which #31 could still happen;
- the opposite: `handle` deletes the guard **before** reading the portfolio and submitting the SELL, so if
  `PortfolioReader.read()` or `ExecutionService.submit` throws, the exit is gone with no SELL and no alert
  (`docs/backlog/tech-debt/2026-11-27-SB-034-2.md`).
